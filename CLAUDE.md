## App description
Leaderboard for a training group, powered by the Strava API.
- Login/signup only via Strava OAuth.
- Strava webhooks notify the app of activity create/update/delete. App fetches the activity and awards points.
- Pages: Login, Leaderboard (ranking table with total points per season), Personal page (activity list: date, moving time, distance, type, competition label, points).

## Scoring rules
- Counted Strava `sport_type`: Run, TrailRun, VirtualRun, Ride, MountainBikeRide, GravelRide, VirtualRide, Swim. E-bikes excluded.
- Duration = `moving_time`, minimum 30 minutes.
- 2 points per activity, 4 if "competition".
- Competition = Strava `workout_type` Race (runs/rides) OR `#competition` tag in the description (any sport, incl. swims).
- Day = `start_date_local`.
- Max 2 scoring activities per user per day (highest points).
- Points are recomputed per user per day on every create/update/delete (never accumulated incrementally).
- Season = name + start date + end date. Only activities inside the season score. Leaderboard is per season. Backfill covers the season range.

## Strava constraints
- New apps start in single-player mode (only the owner's Strava account can authenticate). Upgrade from the API Settings Dashboard raises capacity to 10 athletes (read limits 200 req/15min, 2000/day; overall 400/15min, 4000/day). Beyond 10 athletes, submit the app for review. Plan: develop in single-player mode, upgrade to 10 once there is something to test.
- Webhook payload contains only IDs/event type; fetch the activity with the user's token. Access tokens expire (6h), refresh needed.
- Rate limits (see above): no polling.
- Webhook delivery: Strava expects a 200 within ~2 s, retries a few times, then drops the event. Events sent during downtime are lost; recovered by reconciliation (#31).
- The activity list endpoint returns summaries without `description`; the `#competition` tag needs a detail fetch.
- Strava sends `update` webhooks only for title, sport type and privacy changes: editing the description (`#competition`) or the workout type (Race) after upload sends nothing. Covered by #31: a delayed recheck ~2 h after each create, and the daily reconcile of the last 7 days (details fetched only where the tag can change points).
- Dev needs a public tunnel (cloudflared/ngrok) for webhooks.
- Strava terms restrict showing a user's data to other users; acceptable for a small private group.

## Stack
- Go (latest stable), VS Code with the official Go extension (gopls, delve), golangci-lint.
- HTTP: stdlib `net/http` + `chi` router.
- DB: SQLite (`modernc.org/sqlite`, pure Go) with plain `database/sql`; migrations with `goose`.
- OAuth: `golang.org/x/oauth2`. Sessions: `alexedwards/scs`.
- `log/slog`, config via env vars, stdlib `testing` (table-driven).
- Frontend: Vite + React + TypeScript, built and embedded in the Go binary via `go:embed`.
- Deploy: Docker multi-stage, Fly.io or cheap VPS. CI: GitHub Actions.

## Stretch features (learning value)
- Background worker (channel + goroutine) for webhook events, graceful shutdown with `context`.
- Backfill job with pagination and rate limiting (`golang.org/x/time/rate`).
- Token refresh via `http.RoundTripper` wrapper.
- Weekly/monthly leaderboards.
- Deauthorization handling (delete user data).

## Decisions log
- Router: chi chosen over Gin (net/http compatible, idiomatic, transferable).
- Module path: `github.com/mario595/leaderboard`. Packages under `internal/`, one binary under `cmd/server`.
- Config: `config.Load(getenv func(string) string)` (injected for testability); env vars `ADDR` (default `:8080`), `ENV` (`dev`|`prod`, default `dev`), `LOG_LEVEL` (`debug|info|warn|error`, default `info`). Case-sensitive. Reports only the first error (could use `errors.Join` later).
- Logging: `logging.New(w io.Writer, env, level string)`; text handler in dev, JSON in prod. Logger is passed explicitly, no global.
- HTTP: `NewRouter(logger) http.Handler`; middleware order RequestID, requestLogger, Recoverer (logger outside Recoverer so panics are logged as 500). Request log logs `r.URL.Path` only (query strings may contain OAuth codes).
- Server: `main` calls `run() error`; all four server timeouts set; graceful shutdown with a fresh 10s context.
- Tests: table-driven with `t.Run`, `httptest`, `bytes.Buffer` as log sink, test files named after the file under test.
- CI: GitHub Actions, `test` job (gofmt, vet, test) and `lint` job (golangci-lint v2.14, config in `.golangci.yml` with errorlint, noctx, sloglint, bodyclose, misspell, gofmt). Check configs with `golangci-lint config verify`.
- DB: SQLite via `modernc.org/sqlite` (driver name `sqlite`), `database/sql` pool limited to one connection, pragmas in the DSN (busy_timeout, WAL, foreign_keys), goose migrations embedded with `go:embed` and applied at startup. Times stored as unix-second INTEGERs; the store has an injectable `now` clock for tests. Relative `DB_PATH` resolves from the working directory (launch.json uses cwd = repo root). Tokens stored in plain text (MVP; encrypt later).
- Stretch idea: migrate the hand-written store to `sqlc` once there are several stores.
- Tests: mutation checks catch weak assertions (run them on a copy, never trust a test that has not failed once).
- Seasons (#6): dates stored as TEXT `YYYY-MM-DD`, inclusive bounds, overlap check in a transaction.
- CLI: one binary. `server` or `server serve` runs the web server; `server season create -name N -start YYYY-MM-DD -end YYYY-MM-DD` and `server season list` manage seasons; unknown commands exit with code 2. Shared setup in `openDatabase` (caller closes the DB). Command logic takes the store, args and an `io.Writer` so it is testable.
- Seasons: overlap check relies on SQLite's single writer (and the one-connection pool); on PostgreSQL it would need an exclusion constraint or SERIALIZABLE isolation with retry.
- Strava OAuth (#7): `golang.org/x/oauth2` has `endpoints.Strava`; request scopes `read` and `activity:read`; check the granted `scope` on the callback (users can untick scopes); state in a short-lived cookie; the `auth` package defines the `UserStore` interface it needs (consumer-defined). Never log tokens or the client secret.
- Strava OAuth (#7) is done: `auth.Handler` (Login, Callback), consumer-defined `UserStore` interface with a compile-time assertion in `auth.go`, the HTTP client with a 10 s timeout is injected, tests use a fake Strava (`httptest.NewServer`) and a fake store; error responses to users are generic and never include tokens or internal errors.
- Sessions (#8): `alexedwards/scs/v2` with `sqlite3store` (pure-Go compatible; needs a `sessions` table and has a cleanup goroutine to stop on shutdown), 30-day lifetime, cookie HttpOnly/Lax/Secure-in-prod, `RenewToken` on login, logout is a POST, typed context key for the user id, JSON DTOs (never encode `store.User`, it holds tokens), `NewRouter` takes a `Deps` struct. After login the browser is redirected to `/api/me` until the frontend exists.
- README.md at the root must be kept in sync (Status section) with each ticket.
- Done in #8: `NewRouter(Deps{Logger, Auth, Sessions, Users})`; `LoadAndSave` is applied once as a router middleware; ONE session manager per application, shared by the router and the auth handler (a middleware from one manager cannot serve another's handlers); `/api` is a chi `Route` with `requireAuth` (anonymous visitors get 401 even for unknown API paths); `requireAuth`/`userIDFromContext` live in `httpapi` with an unexported typed context key; the session key is the exported constant `auth.SessionUserIDKey`; the `/api/me` response is a DTO (never `store.User`); logout is POST-only and idempotent; shared test helpers live in `internal/testutil`; golangci-lint uses `run.relative-path-mode: wd` so VS Code can show findings.

Recompute, never accumulate: replays, duplicate events and reconciliation are safe because scoring is idempotent.

Handler: existing file served (`assets/` immutable for a year, others `no-cache`), missing path with an extension 404, anything else `index.html` (`no-cache`), 503 when not built. Router: `GET` and `HEAD /*` registered last, never `r.NotFound` (chi passes it to sub-routers, so unknown `/api` paths would get HTML); chi does not answer HEAD for GET routes. React: `*` route inside `RequireAuth` navigates to `/`. `go.mod` `ignore ./web/node_modules` (the npm package `flatted` ships a `.go` file). `make build` depends on `web-build`. A Go handler that writes nothing answers 200 with an empty body.
- Invitations (#36): `invitations` table (migration 0007, plus nullable `users.invitation_id`); code from `crypto/rand.Text()` (26 base32 chars); zero `time.Time` = no expiry / not revoked (`sql.NullInt64`, `nil` argument writes NULL). `InvitationStore.Create/List/Revoke` (`COALESCE(revoked_at, ?)` keeps the first revoke; `RowsAffected` 0 = unknown code). `UserStore.Login` (UPDATE ... RETURNING by Strava ID, `ErrNotFound` for a new athlete) and `SignUp` (one transaction: conditional `UPDATE invitations SET uses = uses + 1 WHERE ... RETURNING id`, then INSERT; no row = `ErrInvalidInvitation`; a failed insert gives the seat back). `Upsert` stays for test seeding only. `GET /invite/{code}` puts the code in the session (no DB check) and 303s to `/auth/strava`; the callback pops it on every path, `Login`, then on `ErrNotFound` `SignUp`; no or unusable code -> `/login?error=invitation`. Codes are secrets: never logged. CLI `server invite create -uses N [-expires D] | list | revoke -code C` prints `BASE_URL/invite/<code>`. Vite proxies `/invite`. Strava skips the consent screen for an athlete who already authorized the app (`approval_prompt=auto`).
- Go pitfalls from #36: a goose annotation with a typo (`-- + goose Down`) is a plain comment, so the Down SQL runs as part of Up with no error; time layouts use the reference time (`15` = 24-hour, `03` = 12-hour clock); `fail(...)` takes slog key/value pairs, not Printf verbs, and no linter sees through the wrapper; an `if err != nil` placed before an `errors.Is` branch makes that branch unreachable (use a `switch`); a helper that relabels every error (`scanInvitationRow` returning `ErrInvalidInvitation`) can make a test pass for the wrong reason; top-level names share one namespace per package (no per-file scope).
- Backfill (#22): `strava.Client.ListActivities(after, before, page, perPage)` (summaries, no description). One `rate.Limiter` in `strava.API` (`rate.Every(6s)`, burst 5, ~150/15 min), copied into every `ForUser` client, waited on in `get` before each request: webhook worker and backfill share the budget. `RateLimitError.RetryAt(now)` (moved from the worker's `nextWindow`). Queue `backfill_jobs` (migration 0008, unique `(user_id, season_id)`, cascade from users and seasons): `Enqueue`/`EnqueueAll` are upserts that leave a pending job alone and reset a done/failed one (`ON CONFLICT ... DO UPDATE ... WHERE status != 'pending'`, `RowsAffected`; `INSERT ... SELECT` needs `WHERE true` before `ON CONFLICT` in SQLite). `backfill.Import(ctx, client, saver, logger, userID, from, to) (Result{Saved, Details}, error)`: query padded one day each side (UTC filter, local-day points), keep local days in `[from, to]` (string compare of `YYYY-MM-DD`), detail fetch only if `scoring.Activity.Eligible() && !IsCompetition()`, `ErrNotFound` on a detail = skipped, pages of 200 until a short page. `backfill.Runner`: worker pattern (owns its wake channel, buffer 1 + non-blocking send), `maxAttempts = 5`, rate limit -> `RetryAt`, unauthorized -> failed; user or season gone -> done. Unlike the worker, the job runs with the cancellable ctx: shutdown stops the import at its next request and the job is not marked (stays pending, idempotent); marking uses `context.WithoutCancel`. `SignedUp` (an `auth.SignUpListener`, nil = none, errors logged, login goes on) queues the season covering today (UTC). CLI `server backfill -season ID` (`EnqueueAll`). `main` calls `stop()` right after the shutdown signal so a second Ctrl+C kills. Logs: started/done (counts, duration) at Info, pages and detail fetches at Debug. Known race: a webhook delete during an import can re-insert the activity (#31 cleans up).
- Go lessons from #22: Go reuse comes from composition, small interfaces and generics, not hierarchies; for SQL, a little copying beats a shared base (abstract at the third occurrence). A send-only channel (`chan<-`) cannot be received from. Every file in a folder must declare the same package (an editor may guess `package cmd` from the folder). A golangci-lint warning on line 1 of a file is a compile error elsewhere in the package. An interface holding a typed nil pointer is not nil. `signal.NotifyContext` keeps swallowing signals until its `stop()` runs. `context.WithoutCancel` suits short units of work, not half-hour jobs.
- Reconcile (#31): delayed recheck = a copy of the create event with aspect `recheck`, same `event_time` (the unique key dedupes repeated creates), `next_attempt_at` = now + 2 h (`EventStore.ScheduleRecheck`); only `create` schedules one, a scheduling error retries the event. `reconcile.User` = `backfill.Import` (returns `Result.IDs`, saved in order) of the window, then `ActivityStore.IDsBetween` (inclusive local days) and deletes the stored IDs not imported (set as `map[int64]struct{}`, comma-ok lookup); no deletes after a failed import (a partial list looks like deletions). Import's candidate rule is reused instead of fetching every detail. `activity.Service.IDsBetween` delegates to the store so one value satisfies `reconcile.Activities` (embedding both would make `Delete` ambiguous and drop it from the method set). `Scheduler.Run`: a pass at once, then a `time.Ticker` (24 h, `defer ticker.Stop()`); window = UTC date of now minus `windowDays` (7) with `AddDate`; per-member errors logged, `continue`; stops between members on cancel. Logs `reconcile pass`, `reconcile done` (`synced` = saved, changed or not; `deleted`), `reconcile failed`, `reconcile deleted activity`. Third goroutine on the worker's context and `WaitGroup`. Known race: a webhook create between the list and the stored-ID read gets deleted; the 2 h recheck restores it.
- Go lessons from #31: a nil-able comparison does not compile for `struct{}` (use comma-ok `_, ok := m[k]`); an unnamed func type is assignable to any named func type with the same signature (one closure serves `backfill.ClientFunc` and `reconcile.ClientFunc`); `rows.Err()` must be checked with its own `if err := ...` or the outer `err` is wrapped; tests need a clock in a non-UTC zone to catch a missing `.UTC()`.
- Docker (#23): three stages: `web` (`node:24.x-slim`, `WORKDIR /src/web` so Vite's `../internal/spa/dist` lands in `/src/internal/spa/dist`, lock files first, `npm ci` with a cache mount), `build` (`golang:1.27.1`, `go.mod`/`go.sum` then `go mod download`, only `cmd/` and `internal/` copied, frontend `COPY --from=web`, `CGO_ENABLED=0 go build -trimpath -ldflags="-s -w"` with a go-build cache mount, `mkdir /out/data`), runtime `gcr.io/distroless/static-debian12:nonroot` (CA certs, UID 65532, no shell). `/data` copied with `--chown=65532:65532` (without it: "unable to open database file"). `ENV ENV=prod DB_PATH=/data/leaderboard.db ADDR=:8080`; exec-form `ENTRYPOINT ["/server"]` + `CMD ["serve"]` (CLI = `docker run ... leaderboard season list`; shell form needs `/bin/sh` and would swallow SIGTERM). No `VOLUME` (silent anonymous volumes), no `HEALTHCHECK` (no curl; Fly checks `/healthz`). Named volume `leaderboard-data` (a bind mount of `./data` is not writable by 65532). Image ~6.5 MB compressed, 13.4 MB binary. `make docker-build`, `make docker-run` (`--env-file .env` is literal: no quotes or `export`; `-e BASE_URL=http://localhost:8080` overrides it). Checks: `go version -m` shows build settings, `ldd` "not a dynamic executable", `docker export | tar -t` for leaked files.
- Docker lessons from #23: `.dockerignore` is read only at the context root and Docker never reads `.gitignore` (in a subfolder it is ignored and `.env` reaches the context); Make recipe lines must start with a tab and commands on the target line are prerequisites; `--rm` deletes the container on exit, never a named volume.
- Concurrency bugs are intermittent: a missing lock failed 1 of 3 `-race` runs. Run concurrent tests with `-race` (now in CI and `make test`) and `-count` when checking a fix.
- Process lessons: wiring bugs (wrong manager in `main.go`, missing `Users` in `Deps`) are invisible to unit tests of single handlers, so keep at least one test per router wiring and always try the real flow in the browser; compile-time and lint checks do not catch `any` compared with a constant, discarded results, or missing `return` after `http.Error`.
